Binary conversions without memorising anything

Memorising the binary table for 0 to 15 works until an exam asks for 2026. These notes give you two methods that work for any number, a free shortcut to hex and octal, and the one rule behind binary addition.

Video 8:34Read 8 minBeginnerExams · GATE · viva
▶ Watch the episodeDigital Electronics #3Animated, 8:34. Watch first, then use these notes to revise.

In 30 seconds

  • A binary number is a list of which powers of two you used. Take the biggest power that fits, subtract, repeat: 13 = 8 + 4 + 1 = 1101.
  • For big numbers, divide by 2 repeatedly and read the remainders bottom up: 2026 = 11111101010.
  • Once you have binary, hex and octal are just grouping (fours and threes): 2026 = 0x7EA = 37528. And in addition, 1 + 1 = 0, carry 1.

01Method 1: pay with powers of two

Imagine a coin box with only five coins: ₹1, ₹2, ₹4, ₹8 and ₹16, and you may use each coin at most once. How do you pay exactly ₹13? Start with the biggest coin that fits. ₹16 is too big. ₹8 fits, leaving ₹5. ₹4 fits, leaving ₹1. ₹2 is too big for ₹1, so skip it. ₹1 fits, and nothing is left.

Now write a 1 for every coin you used and a 0 for every coin you skipped, in the order 8, 4, 2, 1. That gives 1101, which is 13 in binary. Those coin values are exactly the binary place values from last episode, so this is just place value run backwards.

So 20 = 10100. Always check backwards with place values: 16 + 4 = 20. This method is fast for small numbers, but you need to know the powers of two (1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024 …) up to your number.

02Method 2: divide by two

For a number like 2026 you would need powers up to 1024, and under exam pressure that is where mistakes creep in. Method 2 needs nothing but halving. Think of sharing sweets between two friends: you hand them out in pairs, and if one is left over, that leftover is a 1. If nothing is left, it is a 0.

Divide the number by 2, write the quotient below and the remainder on the right, and repeat with the quotient until you reach 0. Then read the remainders from the bottom up.

Why bottom up? The first remainder tells you whether the number is odd or even, which is exactly the ones place: the smallest bit (LSB). Each later remainder belongs to the next bigger place, so the last remainder is the biggest bit (MSB). A handy check: every even number ends in 0 in binary, every odd number in 1.

03Hex and octal for free

You could convert 2026 to hex by dividing by 16 repeatedly, but there is a faster way you already know. One hex digit is exactly four bits, so take the binary answer and group it in fours, starting from the right. Pad the leftmost group with zeros: 0111 1110 1010. Then read each group: 0111 = 7, 1110 = 14 = E, 1010 = 10 = A. So 2026 = 0x7EA.

Octal works the same way with groups of three, because 8 = 23: 011 111 101 010 = 3 7 5 2, so 2026 = 37528.

Try it: convert any number

Exam corner: the standard conversion methods. Decimal → binary: repeated division by 2 for the integer part (read remainders bottom up), and repeated multiplication by 2 for a fractional part (read the integer parts top down): 0.625 × 2 = 1.25 → 1, 0.25 × 2 = 0.5 → 0, 0.5 × 2 = 1.0 → 1, so 0.62510 = 0.1012. The same division method works for any base: divide by 8 for octal, by 16 for hex. Binary → hex/octal: group in 4s/3s from the binary point outwards.

04Adding in binary

Think of a car's odometer. When a wheel goes past 9, it rolls back to 0 and pushes a 1 into the next wheel. That push is a carry. In binary each wheel has only two digits, so it rolls over much sooner.

InputsSumWriteCarry
0 + 0000
0 + 1110
1 + 11001
1 + 1 + 11111

Those four rows are the whole of binary addition. Add column by column from the right, exactly like decimal, and carry whenever a column reaches 2 or 3.

Every adder inside a processor does exactly this, billions of times a second. The "write" column is the XOR of the inputs and the carry is their AND, which is why an adder can be built from logic gates; we build one in Season 2.

Remember: 1 + 1 = 0, carry 1. That single rule builds every adder.

05Key terms

Power of two
1, 2, 4, 8, 16 … each double the last. These are the binary place values.
Repeated division
Divide by the base, keep the remainder, repeat with the quotient until 0; read remainders bottom up.
Quotient
The whole-number result of a division (13 ÷ 2 = 6).
Remainder
What is left after dividing (13 ÷ 2 leaves 1). In base 2 it is always 0 or 1.
LSB
Least significant bit: the rightmost bit, worth 1. It is the first remainder.
MSB
Most significant bit: the leftmost bit. It is the last remainder.
Padding
Adding leading zeros to complete the leftmost group (111 → 0111). It doesn't change the value.
Octal
Base 8; one digit = 3 bits.
Hexadecimal
Base 16; one digit = 4 bits (A = 10 … F = 15).
Carry
The 1 pushed into the next column when a column's sum reaches the base (2 in binary).

06Practice check

1. What is 25 in binary?

  1. 11001
  2. 10011
  3. 11010
  4. 10101
Show answerA, 11001. 16 + 8 + 1 = 25.

2. In repeated division by 2, which remainder becomes the most significant bit?

  1. The first
  2. The last
  3. The largest
  4. The middle one
Show answerB, the last. The first remainder is the ones place (LSB); the last is the biggest bit, which is why you read bottom up.

3. What is 1011 + 0111?

  1. 10010
  2. 11110
  3. 11001
  4. 01100
Show answerA, 10010. 11 + 7 = 18 = 16 + 2.

Viva: Convert 0.625 to binary.

Show answerMultiply the fraction by 2 and keep the integer parts, top down: 0.625 → 1.25 (1), 0.25 → 0.5 (0), 0.5 → 1.0 (1). So 0.625 = 0.1012 (= ½ + ⅛).

Viva: Why does every even number end in 0 in binary?

Show answerThe last bit is the ones place, which equals the remainder of the number divided by 2. An even number leaves remainder 0, so its LSB is 0.
